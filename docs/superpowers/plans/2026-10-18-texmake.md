# texmake 实施计划

> 状态：已验收（实施完成于 2026-10-18，HEAD a2e4415）。

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建 texmake：读取项目根目录的 `texmake.toml`，按声明的构建方式依次调用 LaTeX 工具，生成 PDF。

**Architecture:** clap 解析命令行，先发现并严格解析配置。校验阶段把配置展开成 `Project`：每套构建方式的变量已替换，工具引用已解析。构建阶段依次判断是否最新、创建输出目录、截断日志、检查工具、执行步骤。只有 `run` 步骤经过系统 shell，其余步骤直接执行 argv。

**Tech Stack:** Rust 2024 edition；clap 4（derive）；serde 1（derive）；toml 0.8（提供 `toml::Spanned` 与行号）；测试用 assert_cmd 2、tempfile 3。

**Spec:** `docs/superpowers/specs/2026-10-18-texmake-design.md`

## Global Constraints

- 单一二进制。texmake 自身不访问网络。
- macOS 与 Linux 必须支持；Windows 尽力支持。
- 配置是本地可信输入，不隔离命令。
- 0.1 的主文档必须位于项目根目录。
- CLI 与错误信息用英文。退出码：0 成功；1 构建失败，含工具缺失；2 配置、用法或环境错误。
- 除 `init` 外不在项目根目录写文件；中间文件全部写入输出目录。
- 错误格式：配置错误 `{path}:{line}:{column}: error: {reason}`；TOML 解析错误 `{path}: {toml 错误}`（含 `line` 与 `column`）；用法与环境错误 `error: {message}`。
- 提示文本固定：`Everything is up to date.`、`Built {pdf}`、`removed {dir}`、`would remove {dir}`。

## Review Focus

1. `output` 经 `..` 或符号链接逃出项目根目录：`check`、`build`、`clean` 都必须拒绝，不得写入或删除根目录之外。测试归 Task 4 与 Task 9。
2. 新鲜 PDF 存在但 `main.tex` 被删除：必须退出 2，不得报“已是最新”。测试归 Task 6。
3. `run` 步骤中的 `${HOME}` 交给 shell；非 `run` 步骤的 `{HOME}` 是配置错误；单引号内的花括号同样按变量处理。测试归 Task 3。
4. 含空格或相对路径的自定义工具命令（如 `scripts/my tool.sh`）不经 shell 也能直接执行；失败信息要指出工具名。测试归 Task 7。
5. `clean` 的删除范围是共享、嵌套输出目录与输出目录内的符号链接。只删除解析后去重的目录集合，绝不删除项目根目录或链接目标。测试归 Task 9。

## File Structure

- `src/main.rs`：入口。发现配置、分派子命令、把 `Error` 映射到退出码。
- `src/cli.rs`：clap 定义。
- `src/error.rs`：`Error`、`ConfigError`、退出码与打印格式。
- `src/config.rs`：配置发现；TOML 严格解析；带 span 的 `RawConfig` 等类型；工具定义解析。
- `src/paths.rs`：输出路径解析、包含判断、去重与嵌套。
- `src/vars.rs`：变量渲染。
- `src/validate.rs`：§6.6 校验，产出 `Project`。
- `src/recipe.rs`：构建方式选择；步骤展开为 `ResolvedStep`。
- `src/up_to_date.rs`：跳过判断。
- `src/build.rs`：构建流水线、日志、工具检查、执行、失败报告。
- `src/clean.rs`：清理。
- `src/init.rs`：初始化。
- `tests/cli.rs`、`tests/acceptance.rs`、`tests/common/mod.rs`：集成测试与夹具。

## Testing conventions

- 集成测试用 `assert_cmd::Command::cargo_bin("texmake")`；每个测试用 `tempfile::TempDir` 建项目。
- `tests/common/mod.rs` 提供 `Fixture`：
  - `Fixture::new()`：写入最小 `texmake.toml` 与 `main.tex`。
  - `write(rel, content)`、`write_toml(toml)`。
  - `fake_tool(name, script)`：在 `bin/` 写可执行脚本，返回 `bin` 路径。
  - `cmd()`：返回设好 `current_dir` 与 `PATH=bin:/usr/bin:/bin` 的 `Command`。
- 假工具脚本用 `sh`。用到脚本的测试标 `#[cfg(unix)]`，Windows 不覆盖。
- 真实 TeX 测试放在 `tests/acceptance.rs`，用 `which` 判断 `xelatex`、`biber`，不存在就跳过。
- cargo 需要写 registry 缓存；沙箱拒绝 `~/.cargo` 时用 `CARGO_HOME=/tmp/texmake-cargo-home cargo test`。
- `Fixture::new()` 写入的默认文件：`texmake.toml` 含 `[project] name = "fixture"`、`main = "main.tex"` 与 `[recipes.release] steps = [{ latex = "xelatex" }]`；`main.tex` 为最小可编译文档。测试需要其他配置时用 `write_toml` 覆盖。
- `tests/cli.rs` 与 `tests/acceptance.rs` 顶部都写 `mod common;`。

- [ ] **Step 3: 实现**

`paths::validate_output`：

1. 词法规范化：拼接 `root` 与 `output`，消去 `.`，`..` 上溯；结果含 `..` 越界时拒绝。
2. 路径存在时 `canonicalize`（跟随符号链接）；不存在时用第 1 步结果。
3. 拒绝：等于根目录；不以根目录开头（用 `starts_with`）；是普通文件；包含 `main_rel`（`starts_with` 比较规范化后的主文档路径）。
4. 返回绝对路径。

`validate::build_plan` 顺序：

1. 解析工具表：字符串简写 → `command`；表只允许 `command`、`args`；缺 `command` 报错；未知键用 span 报错。
2. 构建方式非空，每个 `steps` 非空。
3. `default` 存在则必须指向已定义构建方式。
4. 每套构建方式：`main` 取覆盖值或项目值；校验是根目录直接子文件、扩展名 `.tex`、文件存在；`output` 取覆盖值或项目值，调用 `validate_output`。
