# texmake 需求与设计说明

版本 0.1。状态：已批准。日期：2026-10-18。

## 1 背景

LaTeX 项目常用 latexmk 或 llmk 构建。两者按各自的规则判断编译次数和命令顺序。项目作者需要自己写构建顺序，这两个工具表达不了这个需求，所以新做 texmake。

## 2 目标

texmake 是 make 类工具。texmake 读取文档项目根目录的 `texmake.toml`，按其中声明的构建方式依次调用 LaTeX 工具，生成 PDF。

成功标准：

1. 改构建顺序只改 TOML，不改 texmake 的代码。
2. 一个项目可以有多套构建方式，共用一份配置。
3. 构建失败时能定位到具体步骤和工具输出。
4. 空目录执行 `texmake init` 后能直接构建。
5. 外部工具由配置接入，不需要改 texmake 的代码。

## 3 非目标与反目标

非目标指 0.1 不做的事。反目标指即使做成了也算失败的结果。

非目标：

1. 解析 TeX 日志判断是否需要再次编译。
2. 文件级依赖图和步骤级跳过。
3. 并行执行步骤。
4. 监视文件变化。
5. 安装 TeX 发行版或宏包。
6. 内置 latexmk。
7. 预览、编辑或检查文档内容。

反目标：

1. 内置自动重跑判断，变成 latexmk 的复制品。
2. 配置演变成通用编程语言。
3. 构建依赖隐藏缓存或全局状态。
4. 只支持一种引擎或一种文献工具。
5. texmake 自身依赖 TeX 之外的运行时。

## 4 约束

1. 用 Rust 编写，编译为单个二进制文件。
2. 构建过程不访问网络。
3. 不安装或管理 TeX 发行版与宏包。
4. macOS 与 Linux 必须支持，Windows 宜支持。
5. 配置是本地可信输入，texmake 不隔离命令。
6. 0.1 的主文档必须位于项目根目录。

## 5 术语

| 术语 | 含义 |
|---|---|
| texmake.toml | 文档项目根目录的配置文件 |
| 构建方式 | 一组有序步骤，一次完整构建 |
| 步骤 | 一次 LaTeX 工具调用，或一条 shell 命令 |
| 主文档 | 交给编译器的入口 `.tex` 文件 |
| 输出目录 | 存放 PDF 与辅助文件的目录 |
| 自定义工具 | `[tools]` 中命名的外部可执行文件及其固定参数 |

## 6 配置文件

### 6.1 位置与发现

texmake 从当前目录向上查找 `texmake.toml`，使用最近的配置文件。`--file` 指定其他路径。

配置文件所在目录是项目根目录。全部相对路径以项目根目录为基准。

### 6.2 结构

```toml
[project]
name = "thesis"              # 项目名，必填
main = "main.tex"            # 主文档，必填
output = "build"             # 输出目录，默认 build
default = "release"          # 默认构建方式，可省略

[tools.graphviz]
command = "dot"              # 自定义工具：可执行文件名或路径
args = ["-Tpdf", "-o", "{output}/graph.pdf"]

[recipes.release]
steps = [
  { latex = "xelatex" },     # 内置步骤：调用引擎
  { biber = true },          # 内置步骤：处理文献
  { latex = "xelatex" },
  { latex = "xelatex" },
]

[recipes.draft]
steps = [
  { latex = "xelatex" },
]

[recipes.paper]
main = "paper.tex"           # 覆盖项目级主文档
output = "build/paper"       # 覆盖项目级输出目录
steps = [
  { tool = "graphviz", args = ["{root}/graph.dot"] },
  { latex = "xelatex" },
  { bibtex = true },
  { latex = "xelatex" },
]
```

### 6.3 步骤类型

内置步骤由 texmake 补齐工作目录与常用参数：

| 类型 | 写法 | 作用 |
|---|---|---|
| latex | `{ latex = "xelatex" }` | 调用 pdflatex、xelatex、lualatex |
| biber | `{ biber = true }` | 在项目根目录处理文献 |
| bibtex | `{ bibtex = true }` | 在项目根目录处理文献 |
| makeindex | `{ makeindex = true }` | 在输出目录处理索引 |
| run | `{ run = "sh scripts/gen.sh" }` | 在项目根目录执行命令 |
| tool | `{ tool = "graphviz" }` | 调用 6.5 定义的自定义工具 |

内置步骤可用 `args` 追加参数，例如 `{ latex = "xelatex", args = ["-shell-escape"] }`。`run` 步骤直接写完整命令，不使用 `args`，带 `args` 报配置错误。

每个步骤只能有一个动作键，取 `latex`、`biber`、`bibtex`、`makeindex`、`run`、`tool` 之一。`args` 不是动作键。`biber`、`bibtex`、`makeindex` 的值必须是 `true`。`latex` 只允许 `pdflatex`、`xelatex`、`lualatex`。

### 6.4 变量

`run`、步骤 `args`、`tool` 的 `command` 与 `args` 中可使用变量：

| 变量 | 值 |
|---|---|
| `{root}` | 项目根目录的绝对路径 |
| `{main}` | 主文档路径，相对项目根目录 |
| `{main_stem}` | 主文档去掉扩展名的文件名 |
| `{output}` | 输出目录路径，相对项目根目录 |
| `{name}` | 项目名 |
| `{recipe}` | 当前构建方式名称 |

变量替换规则：

1. 只替换表中的 6 个变量名，替换只做一遍，不递归。
2. `{{` 表示字面 `{`，`}}` 表示字面 `}`。
3. 形如 `{标识符}`（`[A-Za-z_][A-Za-z0-9_]*`）的片段，如果不是表中的变量，必须报配置错误。
4. 其他花括号内容原样保留，例如 `awk '{print $1}'`。
5. `${...}` 先于变量识别：`$` 后紧跟的 `{...}` 不作为变量处理，原样保留，交给 shell 展开。该规则只适用于 `run` 步骤。
6. 非 `run` 步骤（`latex`、`biber`、`bibtex`、`makeindex`、`tool` 的参数）不经过 shell。其中出现 `${...}` 或 `~` 必须报配置错误；`$VAR` 原样传递，不展开。
7. 变量替换先于 shell 处理引号，单引号内同样替换。

### 6.5 自定义工具

`[tools]` 定义外部可执行文件，供 `tool` 步骤使用。

```toml
[tools.graphviz]
command = "dot"              # 必填，可执行文件名或路径
args = ["-Tpdf", "-o", "{output}/graph.pdf"]

[tools]
pandoc = "pandoc"            # 简写：只给命令
```

规则：

1. `tool` 步骤直接执行可执行文件，不经过 shell。
2. 先替换变量，再判断命令类型。替换后的命令含 `/`（Windows 还含 `\`）时按路径解析，相对路径以项目根目录为基准；否则从 `PATH` 查找。
3. 步骤的 `args` 追加在工具定义的 `args` 之后。命令不带隐式参数，输入输出文件写进 `args`。
4. `command` 与 `args` 中可使用 6.4 的变量，替换值按当前构建方式确定。
5. `tool` 步骤在项目根目录运行。

需要管道、重定向或 shell 语法时用 `run` 步骤。

### 6.6 校验

texmake 必须拒绝未知键、缺失必填键和类型错误。错误信息必须包含文件路径、行号、列号、键名和原因。

允许的键：

- `[project]`：`name`、`main`、`output`、`default`。
- `[recipes.<name>]`：`main`、`output`、`steps`。
- `[tools.<name>]`：表形式允许 `command`、`args`；也可写一个字符串，作为 `command` 的简写。

以下情况必须报配置错误：

1. 步骤没有动作键或有多于一个动作键。
2. 引用未定义的工具名，或工具定义缺 `command`。
3. `steps` 缺失或为空，或一个构建方式都没有。
4. `default` 指向未定义的构建方式。
5. `main` 不是项目根目录下的直接子文件，或扩展名不是 `.tex`。
6. `main` 文件不存在。
7. `output` 等于项目根目录、位于项目根目录之外或包含主文档。`output` 校验复用 7.5 的路径解析，输出路径是普通文件时报错。
8. 步骤类型不符合 6.3 的限制。

重复键由 TOML 解析器报错。

## 7 命令行接口

### 7.1 命令一览

```text
texmake                 # 执行默认构建方式
texmake build [name]    # 执行默认或指定构建方式
texmake init [dir]      # 初始化文档项目
texmake clean           # 删除全部构建方式的输出目录
texmake check           # 校验配置文件
```

### 7.2 构建

- 不带参数时执行 `default` 指定的构建方式。
- `default` 未配置时，只有 1 个构建方式则执行该构建方式，否则报错并要求指定名称。
- 构建方式不存在时，报错并列出全部可用名称。

### 7.3 通用选项

| 选项 | 作用 |
|---|---|
| `-f, --file <path>` | 指定配置文件 |
| `-B, --force` | 忽略“已是最新”判断 |
| `-n, --dry-run` | 打印全部命令，不执行，不做跳过判断和工具检查 |
| `-v, --verbose` | 打印完整命令与工具输出 |
| `-q, --quiet` | 只打印错误 |

### 7.4 初始化

`texmake init [dir]` 生成 3 个文件：

1. `texmake.toml`：含 `project` 与默认构建方式。
2. `main.tex`：可编译的最小文档。
3. `.gitignore`：忽略输出目录。

选项：

- `--name <name>`：项目名，默认取目录名。
- `--engine <engine>`：`xelatex`、`pdflatex` 或 `lualatex`，默认 `xelatex`。
- `--language <lang>`：`zh` 或 `en`，默认 `zh`。`zh` 使用 `ctexart`，`en` 使用 `article`。`--engine pdflatex --language zh` 不支持，必须报错退出 2。

目录已有 `texmake.toml` 时必须整体拒绝。其他文件已存在时，保留原文件并跳过，提示跳过的文件。目录不存在时必须创建。

### 7.5 清理

`texmake clean` 删除全部构建方式的输出目录及其内容。

多套构建方式使用不同输出目录时，删除去重后的全部目录。输出目录嵌套时，只删除父目录。

以下情况必须拒绝执行并报错：

1. 输出目录解析后等于项目根目录。
2. 输出目录位于项目根目录之外。
3. 输出目录包含任一构建方式的主文档。

路径解析：先做词法规范化与绝对化；路径存在时再做 canonicalize，跟随符号链接。输出目录是普通文件时拒绝执行。删除目录时不跟随其中的符号链接。`-n` 打印解析后的目标，不删除。

说明：输出目录默认是 `build`，删除后由下一次构建重新创建。警告：删除后，输出目录里的 PDF 不能恢复。

### 7.6 退出码

| 退出码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 构建失败，含工具缺失 |
| 2 | 配置错误、用法错误或环境错误 |

映射：

- 找不到或读不了配置文件、配置错误、用法错误，退出 2。
- 主文档缺失、输出目录无法创建、日志无法写入，退出 2。
- 工具存在但不可执行按缺失工具处理，退出 1。
- 步骤被信号终止时退出 1，报告中写信号编号。

## 8 执行规则

### 8.1 顺序与停止

步骤按配置顺序执行。默认在第一个失败的步骤停止，后续步骤不执行。

### 8.2 工作目录与参数

- 全部相对路径以项目根目录为基准。各步骤的工作目录见下。
- `latex` 步骤在项目根目录运行，参数顺序为：标准参数 `-interaction=nonstopmode -halt-on-error -file-line-error`、输出目录参数、步骤 `args`、主文档。
- `biber` 与 `bibtex` 在项目根目录运行，参数顺序为：步骤 `args`、`<输出目录>/<主文档名去扩展名>`。这样能找到项目根目录的 `.bib` 文件。
- `makeindex` 在输出目录运行，参数顺序为：步骤 `args`、主文档文件名去掉扩展名。
- `tool` 步骤在项目根目录运行，参数顺序为：工具定义的 `args`、步骤的 `args`。
- `run` 步骤在项目根目录运行，不加参数。
- 只有 `run` 步骤通过系统 shell 执行：macOS 与 Linux 用 `sh -c`，Windows 用 `cmd /C`。其余步骤直接执行，argv 不经过 shell。
- `--dry-run` 与失败报告把每个步骤渲染为一行命令：`run` 原样打印，其余步骤按 argv 加引号。

### 8.3 目录与环境

- 构建前创建输出目录，已存在时不报错。
- 环境变量透传，`run` 步骤可用。
- texmake 除 `init` 外不在项目根目录写文件，全部中间文件写入输出目录。

### 8.4 跳过判断

以下条件全部满足时，跳过整条构建方式并提示“已是最新”：

1. 构建方式包含 `latex` 步骤。
2. 主 PDF 存在。
3. 主 PDF 比项目根目录下全部普通文件新。

比较规则：

1. 递归遍历项目根目录，不跟随符号链接。
2. 忽略全部构建方式的输出目录，不只当前构建方式的输出目录。
3. 忽略 `.git` 目录。
4. 0.1 不提供用户自定义忽略规则。

含 `latex` 步骤的构建方式必须比较已加载配置文件的修改时间，`--file` 指定时同样。`--force` 跳过以上判断。`--dry-run` 同样跳过以上判断，打印全部命令。

不含 `latex` 步骤的构建方式每次都运行。

已是最新时直接返回，不创建输出目录，不检查工具。

流程顺序：

1. 加载与校验配置，含主文档存在性。
2. 解析构建方式。
3. 判断是否最新。
4. 创建输出目录。
5. 截断日志。
6. 检查工具。
7. 执行步骤。

`--dry-run` 在判断最新之后直接打印，不创建输出目录、不检查工具。

### 8.5 工具检查

检查在跳过判断之后、创建输出目录之后执行。只检查 `latex`、`biber`、`bibtex`、`makeindex`、`tool` 步骤用到的可执行文件；`run` 步骤不检查。内置工具按名称查 `PATH`；自定义工具按 6.5 的规则解析成路径或命令名，再检查存在且可执行。有缺失时，列出全部缺失工具并退出 1。

### 8.6 失败报告

失败时必须输出：

1. 失败步骤的命令。
2. 退出码。
3. 工具输出的最后 20 行。
4. 完整日志的路径。

完整日志写入输出目录下的 `texmake.log`。

日志在创建输出目录后截断。每步记录渲染后的命令、退出码与输出。stdout 与 stderr 合并，按到达顺序写入。失败报告的最后 20 行取自同一合并流。`-v` 实时输出工具输出。`-q` 仍打印失败报告。工具检查失败时日志为空。

## 9 非功能需求

- **NFR-1 平台**：macOS 与 Linux 必须支持。Windows 宜支持。
- **NFR-2 网络**：构建过程不得访问网络。
- **NFR-3 错误定位**：配置错误必须给出行号与列号。
- **NFR-4 可重复**：相同配置与源码产生相同命令序列，`--dry-run` 可核对。
- **NFR-5 TeX 发行版**：不限定发行版，工具按名称从 `PATH` 查找。

## 10 设计取舍

以下决定由我提出，供评审时逐条核对。

| 主题 | 决定 | 理由 |
|---|---|---|
| 步骤模型 | 有序列表，不建依赖图 | 按用户写的顺序执行，理解成本最低 |
| 增量判断 | 整条构建方式按文件时间戳跳过 | 步骤级判断与 TeX 多遍编译冲突，容易漏编 |
| 配置校验 | 未知键报错 | 拼写错误会静默变成难查的构建问题 |
| 命令执行 | 只有 run 通过系统 shell | 支持管道与已有脚本；配置是本地可信输入 |
| 执行方式 | 其余步骤直接执行 | 路径含空格也不出引号问题 |
| 默认引擎 | xelatex | 中文文档需要 UTF-8 与系统字体 |
| init 模板 | 默认 `ctexart` | 与主要使用场景一致 |
| 命令行语言 | 英文 | 终端编码兼容，日志可复用 |
| 工具定位 | 调用 `PATH` 中的工具 | 不绑定 TeX 发行版 |
| 自定义工具 | 命名工具加固定参数，直接执行 | 复用外部工具；不经 shell 避免引号问题 |
| 主文档位置 | 0.1 限制在项目根目录 | 子目录主文档要换工作目录，留到后续 |
| 输出目录校验 | 所有命令统一校验 | clean 的安全规则不靠单点 |

## 11 待你确认

1. 主文档是否必须放在项目根目录。当前限制在根目录。
2. 增量策略：整条构建方式跳过是否够用，还是要步骤级判断。
3. 多套构建方式是否需要共享公共步骤。当前每套独立写。
4. 是否需要监视文件变化。当前列为非目标。
5. Windows 是否列入 0.1 的支持范围。当前为“宜支持”。

## 12 验收样例

准备一个最小项目：`texmake.toml` 含 `release` 与 `draft` 两个构建方式，主文档 `main.tex`。

1. `texmake check` 打印项目名与全部构建方式，退出码 0。
2. `texmake` 执行 `release`，生成 `build/main.pdf`，退出码 0。
3. 再次执行 `texmake`，提示“已是最新”，不调用 LaTeX。
4. 修改 `main.tex` 后执行 `texmake build draft`，只执行一遍 xelatex。
5. `texmake -n build release` 打印全部命令，不创建输出目录，不检查工具是否存在。
6. `texmake -B` 忽略“已是最新”，重新执行全部步骤。
7. 配置文件写入未知键，`texmake check` 退出码 2，并给出行号。
8. `texmake clean` 删除 `build` 目录；把 `output` 改成 `.` 后，`texmake check` 与 `clean` 都退出 2。
9. 在空目录执行 `texmake init`，生成 3 个文件，随后 `texmake` 可构建成功。
10. 删除 `build` 目录，把 `xelatex` 从 `PATH` 移除后构建，退出码 1，错误信息指出缺失的工具。
11. 含 `biber` 的构建方式在项目根目录找到 `.bib` 文件，在输出目录生成 `.bbl`，PDF 含参考文献。
12. 两套构建方式使用不同输出目录时，`texmake clean` 删除两个目录；输出目录嵌套时只删除父目录。
13. 在已有 `main.tex` 的目录执行 `texmake init`，保留 `main.tex` 并提示跳过。
14. 修改项目根目录的无关文件后执行 `texmake`，texmake 重新构建。
15. 在未构建过的项目中配置 `[tools.graphviz]` 并使用：`-n` 打印 `dot` 命令；`dot` 不在 `PATH` 时构建退出码 1，错误信息含工具名。
16. `texmake init --engine pdflatex --language zh` 退出码 2。
